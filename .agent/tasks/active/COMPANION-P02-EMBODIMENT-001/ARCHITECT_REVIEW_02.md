## Main blocker

COMPANION has approved visual references but does not yet have an approved,
machine-readable production body canon or an approved motion language. The
original Phase 02 directive forced full-scale asset production before those two
foundations and delayed the operator checkpoint required to establish them.

This is the root blocker. Openbox access, native-file transfer, Godot timing,
atlas packaging, CI, and test semantics are real subordinate blockers, but none
of them can make an unapproved body construction and motion language correct.

## Why the previous run failed

Canonical R04 requires a small coherent life-set proof before mass asset
production. Canonical R10 defines the production order as:

1. design lock;
2. motion-language lock;
3. clip production; and
4. packaging.

The Phase 02 execution order instead required the complete 32-family,
256-frame, eight-direction package in one uninterrupted run and prohibited a
return at an internal checkpoint. That sequencing was internally contradictory.
It made Codex optimize measurable proxies before the creative authority was
locked.

The observed causal chain was:

```text
no production canon
+ no intermediate operator gate
+ numeric completion floors
+ self-reported evidence scripts
= procedural pose catalogue
+ direction used as time
+ apparent automated passes
+ large rejected binary batch
```

This was an Architect-level scoping failure as well as an implementation
failure. Patching only the generator would repeat it.

## Evidence findings

### Exact reference state

The exact operator-approved files exist and are authority-bound to:

```text

SHA-256 86ce1f9428f9a998d57e1a99c4245347d5a05e9f0bcf853c2b68065f351bdb56

```

They are complementary art-direction references, not a production rig. They do
not provide approved neutral diagonal production views, named vector parts,
canonical control points, temporal keys, or machine-readable per-frame
landmarks. A production construction model must reconcile them and receive
operator approval.

### Current asset model

`build_assets.py` creates one procedural image per family and direction. Each
clip manifest then places `N, NE, E, SE, S, SW, W, NW` in one ordered frame
array. The current `32 x 8 = 256` result is therefore a directional pose
catalogue, not a temporal animation library.

Visible geometry is shifted with sway, bob, gait, and lean while root and foot
landmarks remain fixed metadata. Current root/contact success therefore proves
only declared values, not rendered stability.

The current generator is deterministic enough to reproduce its own output after
the ZIP metadata correction. That does not make its construction identity-faithful
or its motion semantically correct. Reproducibility and correctness are separate
claims.

### Current contract and runtime

The contract conflates semantic family metadata with concrete direction and
frame sequence. The runtime takes a clip-like `kind` string instead of the
structured body-neutral intent required by R04.

`mon_avatar.gd` appends all directional images to one `SpriteFrames` animation,
passes `duration_ticks / 24.0` as a relative frame duration without setting the
intended animation FPS, and replaces BodyA/BodyB visibility immediately.

`mon_animation_director.gd` does not implement full direction, posture, stage,
affect, energy, pack eligibility, interruption, continuation, or observed
completion semantics. `embodiment_bridge.gd` emits local dictionaries but does
not prove the accepted Phase 01 transport end to end.

Phase 02 can prove a capable body adapter under synthetic structured intents. It
cannot by itself prove continuous organism-caused aliveness before organism
state exists.

### Current evidence system

`validate_assets.py` checks file count, exact pixel uniqueness, canvas, alpha,
safety bounds, and declared metadata. It does not prove temporal motion,
identity fidelity, planted contacts, loop seams, transition compatibility, or
causal behavior.

`transition_matrix.py` treats every pair of known families as allowed and fixes
several failure counters at zero. It does not run Godot or the resident
foundation.

`playback_probe.py` sleeps for five seconds, explicitly starts neither Godot nor
the resident foundation, and reports synthetic frame-time constants.

The inherited contract closeout guesses patterned strings and generated an
invalid `clip_id`. There is no dedicated Phase 02 workflow. The current PR is
therefore red and has no Phase 02 artifact publication.

These patterns repeat an already recorded project learning: identifier/count
coverage and summary booleans do not prove semantic behavior; the named
condition must be induced and the resulting invariant independently observed.

### Current repository and artifact model

PR #9 contains the bulk generated full-canvas frame corpus, duplicate Godot
copies, atlas pages, and the pack ZIP in ordinary Git. This conflicts with
ADR-54. Public branch history must not be rewritten; remove those files from the
final tree and use a squash merge if Phase 02 is eventually accepted.

Candidate CI artifacts are not permanent authority because public Actions
artifacts expire. Accepted immutable runtime packs require both a local
export/restore copy and durable release publication. Build attestations can bind
provenance but do not prove semantic correctness.

### Openbox state

The unavailable dedicated 1366x768 Openbox session is a legitimate blocker only
for the final target endurance gate. Running the present implementation there
would endurance-test the wrong animation model. Do not make target access the
next bottleneck.

## Blocker hierarchy

2. **Immediate:** exact native references are not yet in Codex-accessible

3. **Structural:** family, direction, temporal track, and frame are conflated;

### Gate 3 — concrete track contract and Godot proof

- `MonAnimationFamily` — semantic eligibility and fallback policy;
- `MonAnimationTrack` — one concrete temporal sequence;

Concrete track key:

```text
stage + body_revision + family + direction + posture + variant
```

Use explicit 24 FPS. A two-tick hold is passed as relative duration `2.0`, not
seconds. Drive evidence from actual `frame_changed`, loop, completion,
interruption, degradation, and transport events.

  pack recovery, binary-budget enforcement, artifacts, digests, and tamper

### Gate 5 — scale and target qualification

Only after operator approval:

- expand core motion to all eight directions;
- complete the remaining semantic families and meaningful-drawing floor;
- execute the real 10,000-case campaign through one resident foundation and one
  live Godot process; and
- run two hours on the actual dedicated Openbox target.

## Evidence law

Every acceptance claim must bind:

1. induced stimulus or condition;
2. raw observed event, image, process, or measurement;
3. independent assertion derived from that observation; and
4. a negative or tamper case demonstrating that the assertion can fail.

No success boolean, zero-error counter, performance number, root result,
transition result, or recovery result may be hard-coded or copied from declared
metadata.
